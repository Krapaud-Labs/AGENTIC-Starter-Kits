# Portes de release Agentic 2.0

Une release 2.0 est refusée si une porte est absente, indirecte ou non vérifiée.

- Matrice 1.x vers 2.0 complète.
- Dry-run et migration fixture réussis.
- Rollback testé sur erreur et interruption.
- Runtime canonique et reprise idempotente vérifiés.
- Agents spécialisés réellement créés, affectés et rapportés.
- Contrat de modèle et capacité vérifié.
- Outils shared disponibles sur les plateformes supportées.
- Rapports anonymisés, dédupliqués et auto-corrigés.
- Scénarios de chaos et de reprise réussis.
- Documentation canonique et versionnement cohérents.
- Audit complet uniquement si la carte d audit ou l utilisateur le demande.
- CI complète verte sur le SHA livré.
- PR unique fusionnée vers `dev`.
- Promotion vers `main` laissée à une demande humaine.
